# Dependency licensing

Crabinet's own source and original assets are MIT licensed. Rust and frontend dependencies retain their own copyrights and licenses.

`deny.toml` permits MIT, Apache-2.0 (including LLVM exception), BSD-2-Clause, BSD-3-Clause, ISC, Unicode-3.0, and Zlib for the locked Rust graph. It makes one narrow CDLA-Permissive-2.0 exception for `webpki-roots`, whose CA root data is bundled for OIDC HTTPS connections, MPL-2.0 exceptions for the five `webauthn-rs` crates used for passkeys, and an IJG exception for `jpeg-encoder`, which encodes JPEG thumbnails and declares `(MIT OR Apache-2.0) AND IJG` because its forward DCT is ported from the Independent JPEG Group's code. CI runs `cargo deny check --all-features` on every merge. Pull requests also run GitHub dependency review and reject high-severity dependency findings and GPL/AGPL license families. The frontend lockfile is audited on every merge and release; its production dependencies include Preact and SimpleWebAuthn/browser under MIT and PDF.js (`pdfjs-dist`) under Apache-2.0, while development packages are not shipped as runtime files. `pdfjs-dist` declares an optional dependency on `@napi-rs/canvas` (MIT) for Node.js rendering; it is never bundled into the browser frontend.

Every release publishes SPDX JSON SBOMs for each binary archive and architecture-specific OCI image. The current binary archive SBOM identifies the packaged files but does not enumerate the statically linked Rust crates, so it must not be used as a complete dependency license inventory. The locked Rust and frontend manifests provide package versions; [third-party licenses](../THIRD_PARTY_LICENSES.md) maps the bundled Apache-2.0, MPL-2.0, CDLA-Permissive-2.0, IJG, and PDF.js BSD components to their full license texts. Releases built from this revision include that file and Crabinet's root [MIT license](../LICENSE) in the archive and in the image's `/licenses/` directory. The root `LICENSE` applies only to Crabinet's own source and original assets; the other terms apply to their respective bundled components.

The image thumbnail decoders are pure Rust crates from the image-rs project (`png`, `gif`, `jpeg-decoder`, and `image-webp`, with `fdeflate`, `flate2`, `miniz_oxide`, and `weezl`), all MIT OR Apache-2.0. Folder and selection archives deflate text entries through `flate2` directly, with its default pure-Rust `miniz_oxide` backend (MIT OR Zlib OR Apache-2.0) and no C zlib, so the archive writer adds no package to the locked graph. No permissively licensed pure-Rust AVIF or HEIC decoder exists (the available ones are C libraries or MPL-licensed parsers over C), and RAW demosaicing crates are LGPL, so those formats are not decoded. Thumbnails are encoded by `png` and by `jpeg-encoder`, a pure-Rust crate without dependencies, built without its `simd` feature so that it forbids unsafe code.

Apart from the CCADB data terms, the IJG terms, and the PDF.js data and decoders described below, no dependency in the currently locked distributable graph supplies a separate `NOTICE` file or attribution that must be copied into the release archive. The IJG terms require the documentation accompanying an executable to state that "this software is based in part on the work of the Independent JPEG Group"; [third-party licenses](../THIRD_PARTY_LICENSES.md), which every release archive and image includes, carries that statement and the IJG license text. Apache, MIT, BSD, ISC, Unicode, and Zlib terms and upstream copyright notices still apply to their respective components. A dependency update that introduces a package-specific notice, nonstandard license file, embedded asset, or attribution requirement must add that notice to release artifacts and update this document before merge; passing `cargo-deny` alone is not sufficient evidence for that case.

Release reviewers should compare the locked dependency diff and third-party license mapping with this policy. The Apache crate table is derived from `cargo metadata --locked --filter-platform` for both `x86_64-unknown-linux-musl` and `aarch64-unknown-linux-musl`, following normal dependency edges from Crabinet. Source distributions preserve dependency metadata through `Cargo.lock`, `web/package-lock.json`, and package manifests. Update the license mapping when the locked runtime graph or bundled data changes.

The production frontend build copies a fixed subset of `pdfjs-dist` files unchanged into `assets/pdfjs-<version>/` (see `pdfjsAssets` in `web/vite.config.ts`) because PDF.js loads them by file name: the Adobe CMaps and Foxit standard fonts (BSD-3-Clause) and the JavaScript builds of the OpenJPEG (BSD-2-Clause) and PDFium JBIG2 (BSD-3-Clause, with Apache-2.0 Mozilla glue) image decoders. Their notices are reproduced in [third-party licenses](../THIRD_PARTY_LICENSES.md#pdfjs-data-and-decoders). The package's Liberation Sans fonts are GPL-2.0 with a font exception and are deliberately not copied; neither are its WebAssembly binaries or ICC profile. A `pdfjs-dist` update must re-check that file list, the version in the third-party license mapping, and any new license file in the package.
