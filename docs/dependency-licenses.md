# Dependency licensing

Crabinet's own source and original assets are MIT licensed. Rust and frontend dependencies retain their own copyrights and licenses.

`deny.toml` permits MIT, Apache-2.0 (including LLVM exception), BSD-2-Clause, BSD-3-Clause, ISC, Unicode-3.0, and Zlib for the locked Rust graph. It makes one narrow CDLA-Permissive-2.0 exception for `webpki-roots`, whose CA root data is bundled for OIDC HTTPS connections, and MPL-2.0 exceptions for the five `webauthn-rs` crates used for passkeys. CI runs `cargo deny check --all-features` on every merge. Pull requests also run GitHub dependency review and reject high-severity dependency findings and GPL/AGPL license families. The frontend lockfile is audited on every merge and release; its production dependencies include Preact and SimpleWebAuthn/browser under MIT, while development packages are not shipped as runtime files.

Every release publishes SPDX JSON SBOMs for each binary archive and architecture-specific OCI image. The current binary archive SBOM identifies the packaged files but does not enumerate the statically linked Rust crates, so it must not be used as a complete dependency license inventory. The locked Rust and frontend manifests provide package versions; [third-party licenses](../THIRD_PARTY_LICENSES.md) maps the bundled Apache-2.0, MPL-2.0, and CDLA-Permissive-2.0 components to their full license texts. Releases built from this revision include that file and Crabinet's root [MIT license](../LICENSE) in the archive and in the image's `/licenses/` directory. The root `LICENSE` applies only to Crabinet's own source and original assets; the other terms apply to their respective bundled components.

Apart from the CCADB data terms, no dependency in the currently locked distributable graph supplies a separate `NOTICE` file that must be copied verbatim into the release archive. Apache, MIT, BSD, ISC, Unicode, and Zlib terms and upstream copyright notices still apply to their respective components. A dependency update that introduces a package-specific notice, nonstandard license file, embedded asset, or attribution requirement must add that notice to release artifacts and update this document before merge; passing `cargo-deny` alone is not sufficient evidence for that case.

Release reviewers should compare the locked dependency diff and third-party license mapping with this policy. The Apache crate table is derived from `cargo metadata --locked --filter-platform` for both `x86_64-unknown-linux-musl` and `aarch64-unknown-linux-musl`, following normal dependency edges from Crabinet. Source distributions preserve dependency metadata through `Cargo.lock`, `web/package-lock.json`, and package manifests. Update the license mapping when the locked runtime graph or bundled data changes.
